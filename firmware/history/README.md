# Firmware history: three targets, three generations

The data node was rewritten twice as the bench grew. All three generations are bare-metal C
against raw register addresses: no HAL, no libc, no floating point. Only the third one,
`../main.c`, is the shipped firmware; the two files here are kept because the design history
explains why the shipped version looks the way it does, and because each generation produced
part of the recorded dataset.

| | `h743_main.c` | `g474re_main.c` | `../main.c` (shipped) |
|---|---|---|---|
| Board | NUCLEO-H743ZI2 | NUCLEO-G474RE (MB1367D) | NUCLEO-F401RE |
| Clock | HSI 64 MHz | HSI16 16 MHz | HSI 16 MHz |
| Speed command | DAC1_OUT2 on PA5: analog voltage into SV | TIM3_CH2 PWM on PA7, 1 kHz | TIM3_CH1 PWM on PB4 (D5), 1 kHz, duty = rpm / 2310 |
| Driver enable | hardwired (EN strapped) | hardwired (EN strapped) | PA8 (D7), open-drain, released at boot and at speed 0 |
| Hall inputs | PD5/6/7, **polled** in the main loop | PA8/PA9/PA10 | PA10/PB3/PB5, **EXTI on both edges** into a ring buffer |
| Analog | none | ADC1: bus current, VREFINT, PC0 | ADC1: A0 current (INA240A2), A1 NTC, VREFINT |
| Accelerometer | none | none | KX134-1211 over bit-banged I²C on PB9/PB8 (D14/D15) |
| Speed input from host | no: USER button steps a table | no: USER button steps a table | yes: `S<rpm>\n` over an interrupt-driven USART2 RX |
| Serial | USART3 on PD8 | USART2 on PA2/PA3 | USART2 on PA2/PA3 |
| CSV columns at 10 Hz | 10 | 16 | 44, including an on-device `fault_code` |
| Classification | none: host side only | none: host side only | on-device: limit ladder, then a 33-node decision tree, agreement check, persistence filter |

## What changed, and why

**H743 → G474RE.** The H743 build proved the concept: count Hall edges, derive RPM, speed
ripple, Hall-state legality and coast-down time, and stream ten CSV columns. Its speed command
was a DAC voltage, and its Halls were polled from the main loop, so any long operation in that
loop showed up as timing jitter in the very features being measured. The G474RE rewrite
replaced the DAC with a 1 kHz PWM speed command (what the BLD-510B actually wants), added an
ADC chain for bus current, and (the substantive change) added per-revolution frequency
analysis of the Hall edge intervals.

**The Q10 DFT.** An 8-pole motor gives four pole-pairs and 24 Hall edges per mechanical
revolution. Every revolution the G474RE build takes those 24 intervals from a ring buffer and
runs an integer DFT against fixed Q10 (×1024) cosine/sine tables, extracting two bins:

- **bin 1**: the once-per-mechanical-revolution component, published as `mech1x_permil`.
  This is the imbalance / eccentricity signature: it appears when mass is off-centre and it
  scales with speed.
- **bin 4**: the six-edge (once-per-electrical-cycle) component, published as
  `elec_permil`. This is fixed Hall-spacing and magnet-spacing error, an electrical
  asymmetry baked into the motor that does not change with condition.

Separating the two matters because a plain jitter metric cannot tell them apart. Without the
split, a motor's permanent Hall-spacing error sits in the timing statistics forever and looks
like a standing mechanical 1x imbalance, which either raises the healthy baseline until real
imbalance is invisible or trips the classifier on a motor that is fine. `period_std_permil`
(the overall interval spread) was added alongside them so the total and the two named
components can be compared. All of it is integer-only; magnitudes come from a 64-bit integer
square root, and results are scaled to per-mille of the mean interval, so the build needs no
soft-float.

**G474RE → F401RE.** The final move was driven by what the bench needed rather than by MCU
capability: temperature (NTC on A1), vibration and orientation (KX134 over bit-banged I²C,
after the hardware I²C BUSY errata on this part made the peripheral path not worth fighting),
software speed control over the serial link instead of a button, and an enable line the
firmware actually controls. That last one fixed a real measurement bug: with EN strapped to
COM the driver is always armed, and at SV = 0 it leaves roughly 10 mA of standby bias in the
windings whenever the rotor parks in Hall sector 2 or 4, which poisoned every current zero
re-anchor taken in those sectors. Hall capture also moved into EXTI interrupts so that ADC
conversions and the ~1.2 ms accelerometer read can no longer corrupt edge timing. The Q10 DFT
carried over from the G474RE build unchanged.

## Caveats

- These two files are historical snapshots. They are not built by `../Makefile`, which targets
  the F401RE, and they reference a `speeds_gen.h` generated by the bench app for their own
  speed tables.
- Data recorded under the pre-F401RE generations is in `data/commissioning_unmounted/`; every
  session there records `firmware_version: motor.elf-2026-06-19`, and the whole campaign is
  tagged `valid_for_classifier = false` for the reasons given in `data/README.md`. Its rows
  carry `mech1x_permil` / `elec_permil` but no accelerometer, temperature or current columns,
  which is consistent with a build of the middle generation.
